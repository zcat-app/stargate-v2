# Offline encrypted archives and staged import

This standalone Java 25 module provides offline `pack`, `verify`, and `stage`
commands plus a separate stopped-volume import command. It does not collect
snapshots, stop or start services, call Docker, prepare restored credentials,
create volumes, activate an installation, or establish snapshot consistency.
The module is part of the root Maven reactor. Docker capture/import adapters
are separate commands; use the Java/Bash commands below for this core.

Read [Offline encrypted archives](../docs/offline-encrypted-archives.md) for
the full trust model and recovery limitations, and
[Offline volume import with Java](../docs/offline-volume-import-java.md)
for the separate import command. A successful archive check proves neither
source completeness nor creator identity, a trusted timestamp or rollback
protection. Anyone with the public recipient can make a valid ciphertext.
A five-root archive does not prove that the source installation had no Nym
state; include both Nym roots when that state must be retained.

## Prerequisites

Use Linux with glibc providing `statx` and
`posix_spawn_file_actions_addclosefrom_np`, Java 25, and a local filesystem
supporting file and directory `fsync`, hard links and
`renameat2(RENAME_NOREPLACE)`. Run as an unprivileged caller with matching real
and effective UID and GID. Prevent concurrent writers to source, key, binary,
archive, output and work paths for the whole operation. All paths are absolute
and normalized; symlink components are rejected.

Select a native age v1.3.2 ELF and independently authenticate its SHA-256 using
the release policy described in the archive guide. A binary and digest obtained
solely from the same untrusted source do not establish provenance. The supplied
binary is pinned by descriptor, checked against that digest and run without
privilege gain. Supply exactly one native X25519 identity, a single-link regular
file owned by the caller with mode `0600`; plugins, SSH keys, passphrases and
multiple identities are unsupported. No keys are generated by these commands.

The caller-owned source, output, verification and staging parents must have
mode `0700`. Every source volume root must be owned by the caller's effective
UID and GID and have mode `0700`. The source set must contain exactly `app-data`, `tor-data`,
`tor-control`, `i2p-data`, and `i2p-control`; `--nym` adds both `nym-data` and
`nym-secrets`. Source and output parents cannot contain each other. The identity
must be outside both the source and the output parent. For verification and
staging, both identity and ciphertext must be outside the work/output parent.
No ownership is remapped.

## Commands

After building the module, replace the placeholders with already prepared paths
and independently verified values. The recovery key and recipient must match.

```sh
bash tools/with-toolchain.sh mvn --offline -f backup-tools/pom.xml package
JAVA_TOOL=backup-tools/target/stargate-backup-tools-0.1.0-SNAPSHOT.jar
AGE=/absolute/verified-age/age
AGE_SHA256=VERIFIED_LOWERCASE_SHA256
IDENTITY=/absolute/private-keys/identity
RECIPIENT=age1_REPLACE_WITH_NATIVE_RECIPIENT

bash tools/with-toolchain.sh java --enable-native-access=ALL-UNNAMED -cp "$JAVA_TOOL" app.zcat.stargate.backup.OfflineVerify \
  --age "$AGE" --age-sha256 "$AGE_SHA256" --identity "$IDENTITY" \
  pack --source /absolute/stopped-snapshot-set --output /absolute/private-archives/backup.age \
  --recipient "$RECIPIENT"

bash tools/with-toolchain.sh java --enable-native-access=ALL-UNNAMED -cp "$JAVA_TOOL" app.zcat.stargate.backup.OfflineVerify \
  --age "$AGE" --age-sha256 "$AGE_SHA256" --identity "$IDENTITY" \
  verify --archive /absolute/private-archives/backup.age --work-dir /absolute/private-verify-work

bash tools/with-toolchain.sh java --enable-native-access=ALL-UNNAMED -cp "$JAVA_TOOL" app.zcat.stargate.backup.OfflineVerify \
  --age "$AGE" --age-sha256 "$AGE_SHA256" --identity "$IDENTITY" \
  stage --archive /absolute/private-archives/backup.age --output /absolute/private-stage-parent/staged
```

Add `--nym` to `pack` only when both matching Nym roots are supplied. Only exit
status 0 with `ENCRYPTED_ARCHIVE_VERIFIED` confirms pack or verify success;
only exit status 0 with `OFFLINE_STAGE_CREATED_RECOVERY_REQUIRED` confirms stage
publication. The summary contains only the entry count, payload bytes and Nym
selection. Existing output names, including symlinks, are never replaced.

Pack traverses the stopped source through held no-follow descriptors, writes a
bounded canonical uncompressed USTAR spool, encrypts it, fully decrypts it with
the supplied identity, compares the plaintext digest and validates the archive
before atomic no-replace ciphertext publication. Verify and stage authenticate
the complete age stream before inspecting any archive data. The age child has a
restricted environment, no unrelated inherited descriptors, a 30-minute timeout,
zero core-dump limit, and bounded ciphertext/plaintext file size. The format
rejects unsafe paths, links, special files, extensions, unsupported metadata,
incomplete roots, nonzero padding, missing terminators and concatenated data.
The limits are 8 GiB plaintext tar, 2 GiB per file, 100,000 entries, 32 path
components and 255 UTF-8 path bytes where USTAR can represent them.

Stage validates all members before descriptor-relative extraction into a new
private tree. Every archived UID and GID must equal the caller's effective UID
and GID, every volume root must be `0700`, nested directories need owner `rwx`,
and regular files need owner read permission. These stage requirements align
with the separate importer. An
archived credential-recovery marker must be a regular `0600` file; its content
is replaced with a newly synced marker before publication. An archived
`app-data/volume-import-incomplete` is rejected, regardless of type. Identity
recovery transaction markers are preserved. A successful stage contains restored
credentials and remains offline; the gate only protects software that honors it.
Run the separately documented credential recovery procedure before later use.
Verification checks archive integrity and structure independently of staging
eligibility: a verified archive may still be rejected by stage for these
ownership or mode requirements. Packing also does not assert that every nested
member meets stage eligibility.

Normal completion and failure remove the operation's known private spool files
and sync the directories. If cleanup or publication durability cannot be
confirmed, the command fails and reports the private `.stargate-backup-*`
location for offline inspection; persistent storage faults can prevent even that
location from being retained. Any apparent output on failure is unconfirmed.
SIGTERM and Ctrl-C initiate cleanup. SIGKILL, power loss or filesystem faults
can leave plaintext behind. Deletion is not secure erasure: use encrypted scratch
storage and appropriate swap and backups. These operations are not a storage
failure or power-loss certification.

## Tests

Run `bash tools/with-toolchain.sh mvn -o -f backup-tools/pom.xml test` when Maven dependencies are cached.
The native integration tests are opt-in: set `STARGATE_TEST_AGE` and
`STARGATE_TEST_AGE_KEYGEN` to independently obtained v1.3.2 linux-amd64
binaries. Their expected digests are checked before execution, and tests create
fresh synthetic keys and temporary roots. An additional recovery-chain test
requires `STARGATE_TEST_RECOVERY_JAR` pointing to the matching locally built
proxy JAR. No test requires real volumes, existing keys, services or Docker.
