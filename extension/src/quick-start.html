Start browsing with Stargate

One browser connection: web through Nym, .onion through Tor, and .i2p through I2P. Use a regular browser window.

Ask the person who runs your server for the extension download and its HTTPS server address. Prepare your browser first, then ask for a fresh one-time access code for each browser when you are ready to connect. You do not need an account or an administrator login.

Firefox: install and prepare

Firefox 140 or later is required. If you install a Mozilla-signed store version, use its Add to Firefox button and review the authentication, browsing-activity and website-content disclosures. The published listing is Stargate on Mozilla Add-ons. For an unsigned test XPI, use the temporary-loading steps below; the normal installer may say it is not verified.

  1. Save the Firefox XPI somewhere you can find again. You do not need to extract it.
  2. Open about:debugging#/runtime/this-firefox. Choose Load Temporary Add-on…, then select the downloaded Firefox XPI.
  3. In a new tab, open about:addons. Select Extensions → Stargate → Details, then set Run in Private Windows to Allow.
  4. Changing that permission may close setup. Open the browser’s puzzle-piece Extensions menu, choose Stargate, then I have an access code. Follow Connect below.
Firefox needs that permission to change proxy settings even in regular windows. Use regular windows with Stargate.

The temporary extension is removed when Firefox exits. Load the same package again and check for saved access before asking for another code. Do not disable signature checks.

Brave: install and prepare

  1. Save and extract the Brave ZIP into a folder you will keep.
  2. Open brave://extensions, enable Developer mode, choose Load unpacked, and select the folder containing manifest.json.
  3. In brave://settings/privacy, switch off both Private window with Tor and Only resolve .onion addresses in Tor windows. Stargate uses Tor on your server. Check these choices yourself; the extension cannot confirm them.
  4. Open the puzzle-piece Extensions menu, choose Stargate, then I have an access code. Follow Connect below.
Do not use Brave private windows with Stargate. Private windows can connect directly, outside Stargate. The extension’s warning does not block that traffic.

Connect and review

  1. On Stargate’s Set up this browser page, complete 1. Prepare your browser.
  2. Under 2. Connect this browser, paste the operator’s server address and access code, then select Connect this browser. The server address looks like https://gate.example.org:9443; use your operator’s address, not this example or the extension download URL. Do not enter an administrator token. If the browser offers to save this code as a password, choose Not now; it is single-use.
  3. Review 3. Browser settings applied: check the server address and browser-preparation note. In Brave the Tor options remain a manual check. Saved access remains valid after the one-time code expires.
  4. Fully quit and reopen the browser before sensitive browsing. In Firefox, if it was loaded temporarily, load the same XPI again using Load Temporary Add-on…. Open Stargate from the Extensions menu to check that it uses saved access; no new code is needed. Existing connections can otherwise keep their previous route.
  5. Use your normal address bar and ordinary links. Open a page to check access. View connection status opens observations; applied settings and past responses do not prove a website is reachable.

Each browser, profile or device needs its own code. Codes are single-use: five minutes by default, or 24 hours if the operator chooses. Ask the operator for a fresh code when one is expired or used. If access was saved but settings were not applied, finish the browser step and use Apply browser settings; do not redeem another code.

Optional: IPFS addresses

You can skip this for ordinary browsing. In Stargate, use Optional: set up IPFS links after connecting, or Settings → IPFS address-bar links later.

  • Firefox: accept Open Link for Stargate. If it offers System Handler, cancel. Open about:preferences#downloads, search for ipfs under Files and applications, and choose Use Stargate IPFS through Nym. Retry the address. If Stargate is absent, ask for help rather than selecting an external application or removing pairing.
  • Brave: select Enable IPFS links, then Allow in the browser prompt. Keep that tab open until approval. If needed, inspect brave://settings/handlers.

Approve the handler before entering an ipfs:// address; unhandled input may be searched. Content uses the configured HTTPS gateway through Nym. The gateway may be unavailable, and Stargate does not verify content hashes. The IPFS tool remains available.

Help, disconnect and updates

  • Code invalid, expired or used: request a fresh code for this browser. If pairing’s result is unknown, ask the operator to check for an unused device before issuing another code. Do not repeatedly retry redemption.
  • Page fails: inspect Connection observations. A cold I2P connection can take minutes. Retry forms or uploads only when safe: they may already have arrived.
  • Server or certificate problem: contact the operator. Keep Stargate’s settings on while diagnosing; do not follow a browser’s suggestion to switch to direct/no proxy or bypass certificate warnings.
  • Disconnect: choose Disconnect, then confirm. Saved access is kept; Connect reuses it. New connections use your previous browser settings and may connect directly. Existing streams may keep their previous route.
  • Update: in Brave, replace files in the same extracted folder, then use Reload on Stargate’s brave://extensions card. For a temporary Firefox install, replace the downloaded XPI at the same location, fully quit and reopen Firefox, then load that XPI with Load Temporary Add-on…. Check the version shown in Stargate and its applied settings. Avoid uninstalling or clearing extension data when updating; a new profile or removed data may require a fresh code.

Settings → Appearance offers Clear, Stargate and Observatory. Advanced mode is optional. Each route keeps its network; an unavailable route does not fall back to another network or direct access.

This guide is bundled locally and loads no scripts, fonts, images or external resources. The VPS operator remains trusted with routing metadata and HTTP content; HTTPS content stays encrypted to the destination.
